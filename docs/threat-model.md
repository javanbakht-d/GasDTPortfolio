# مدل تهدید و کنترل‌های امنیتی — NIGC-DTG

مرجع ارزیابی: OWASP Top 10 (2021) و OWASP ASVS (سطح مناسب سامانه سازمانی داخلی). این مدل در زمان توسعه نگهداری می‌شود و باید پیش از استقرار عملیاتی بازبینی شود.

## موجودیت‌های قابل اعتماد و غیرقابل اعتماد

- **قابل اعتماد**: پایگاه داده سامانه، منطق سمت سرور (API routes)، پیکربندی سرور.
- **غیرقابل اعتماد**: هر ورودی کاربر، محتوای فایل‌های بارگذاری‌شده، هرگز خروجی مستقیم مدل زبانی به‌عنوان واقعیت، هدرها/کوکی‌ها.

## تهدیدها و کنترل‌های پیاده‌شده

| # | تهدید | سطح | کنترل پیاده‌شده |
|---|---|---|---|
| T1 | دور زدن احراز هویت / دسترسی بدون نشست | بالا | نشست تصادفی ۱۲۸ بیتی در جدول Session با تاریخ انقضا؛ کوکی httpOnly + SameSite=Lax؛ تمام APIها با `requireAuth` |
| T2 | IDOR — دسترسی به رکورد واحد دیگر | بالا | فیلتر محدوده سازمانی در کوئری‌ها سمت سرور (GLOBAL_VIEW_ROLES در برابر واحد کاربر)؛ بررسی مالکیت رکورد در GET/PATCH با شناسه صریح |
| T3 | تشدید مجوز از مسیر API | بالا | `requirePerm` روی هر مسیر حساس؛ مجوزها فقط از نقش‌های تخصیص‌یافته؛ پنل کاربری فقط رابط است |
| T4 | تزریق SQL | بالا | Prisma ORM با پارامتری‌سازی خودکار؛ بدون رشته‌های SQL خام |
| T5 | XSS | بالا | React escaping پیش‌فرض؛ بدون `dangerouslySetInnerHTML` در مسیر داده کاربر؛ خروجی دستیار هوشمند به‌صورت متن رندر می‌شود |
| T6 | CSRF | متوسط | SameSite=Lax + استفاده صرفاً از JSON در API (بدون تغییر حالت با GET) |
| T7 | Prompt Injection روی دستیار هوشمند | متوسط | قواعد سیستمی در پیام سیستم (نادیده‌گرفتن دستورات تغییر قواعد)؛ بازیابی فقط از رکوردهای مجاز کاربر در کد سمت سرور؛ بدون ابزار اجرایی برای مدل؛ خروجی با برچسب «پیش‌نویس تولیدی هوش مصنوعی» |
| T8 | افشای اطلاعات حساس از مسیر دستیار | بالا | لایه بازیابی قبل از مدل، فقط رکوردهای در محدوده مجوز کاربر را به کانتکست می‌دهد؛ دستیار مجوز خود را از پرسش کاربر افزایش نمی‌دهد |
| T9 | حملات جست‌وجوی گذرواژه | متوسط | bcrypt با cost مناسب؛ پیام خطای یکسان «نام کاربری یا گذرواژه نادرست»؛ محدودیت نرخ ورود (`rateLimit` بر پایه IP/کاربر) |
| T10 | ثبت اسرار در لاگ/مخزن | بالا | لاگ‌ها بدون گذرواژه/توکن؛ `.env` در .gitignore؛ فایل نمونه `.env.example` بدون مقادیر واقعی |
| T11 | تغییر بی‌ردپای داده‌های مصوب | متوسط | جدول ActionUpdate/DocumentVersion/BaselineChange؛ سوابق ممیزی AuditLog جداگانه برای عملیات حساس |
| T12 | نشست‌های کاربر غیرفعال | متوسط | غیرفعال‌سازی کاربر، حذف نشست‌های فعال وی؛ بررسی isActive در هر درخواست |
| T13 | بارگذاری فایل مخرب | متوسط | در این نسخه بارگذاری فایل به نسخه رسمی اسناد محدود و در پنل مدیریت کنترل می‌شود؛ فیلد needsUpload صادقانه «نیازمند بارگذاری» را نشان می‌دهد. برای عملیاتی‌شدن: اعتبارسنجی نوع/حجم/آنتی‌ویروس الزامی است (بند باز) |
| T14 | مصرف بی‌رویه مدل زبانی | متوسط | محدودیت نرخ ۲۰ پرسش در ۱۰ دقیقه برای هر کاربر؛ امکان قطع کل دستیار از تنظیمات (`ai.enabled`)؛ ثبت مصرف/خطا در ممیزی |

## محدودیت‌های شناخته‌شده محیط سندباکس (برای استقرار عملیاتی الزامی است)

1. **TLS**: ترمیناسیون TLS در پراکسی سازمانی/گیت‌وی انجام شود؛ کوکی‌ها در production باید `Secure` شوند.
2. **محدودیت نرخ سراسری و WAF**: در لایه شبکه تکمیل شود.
3. **پشتیبان‌گیری/بازیابی**: برنامه زمان‌بندی‌شده + آزمون بازیابی مستند شود (SQLite فایل است؛ در production PostgreSQL + پشتیبان‌گیری مدیریت‌شده).
4. **2FA / SSO-OIDC**: ساختار مدل کاربر آماده است؛ اتصال به هویت سازمانی نیازمند تصمیم و زیرساخت است (بند باز).
5. **جدا بودن داده نمونه از واقعی**: کاربران/داده‌های seed صرفاً آزمایشی هستند و باید پیش از بهره‌برداری واقعی بازنشانی شوند (اسکریپت seed جدا از داده عملیاتی).
