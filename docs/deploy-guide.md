## گام ۰ — تحلیل وضعیت فعلی و انتخاب پلتفرم

### وضعیت فعلی شما (بر اساس تصاویر ارسالی)

**۱) Neon — دو پروژه تکراری:** در حساب Neon شما **دو پروژه یکسان با نام `gasdt`** ساخته شده (هر دو در AWS US East). مصرف هر دو تقریباً صفر است — یعنی فقط مراحل اولیه bootstrap اجرا شده و داده عملیاتی‌ای از دست نمی‌رود.

**۲) Vercel — دو مشکل پیکربندی دامنه:**
- دامنه `gasdt.app` وضعیت **Invalid Configuration** دارد؛ یعنی رکوردهای DNS آن هنوز به Vercel اشاره نمی‌کنند.
- دامنه اصلی `gas-dt-portfolio.vercel.app` روی **Redirect 307 به `gasdt.app`** تنظیم شده است؛ نتیجه: هر بازدید از آدرس خود اپ، به دامنه‌ای پرت می‌شود که هنوز کار نمی‌کند → **سامانه در هیچ آدرسی بالا نمی‌آید.**
- این تنظیم در گام ۸ اصلاح می‌شود؛ فعلاً فقط بدانید که مشکل «باز نشدن سایت» از اپ نیست — از redirect است.

## گام ۱ — پاکسازی نصب‌های قبلی (۵ دقیقه)

### ۱-۱) حذف دو پروژه تکراری Neon

1. **https://neon.com** → ورود (اگر باز نشد، همان روشی که قبلاً استفاده کردید).
2. پروژه اول `gasdt` را باز کنید → پایین منوی کناری **Settings** → بخش انتهایی **Danger** → دکمه **Delete project** → نام پروژه را تأیید کنید.
3. همین کار را برای **پروژه دوم** هم انجام دهید.
4. ✅ حالا حساب Neon شما خالی است — دیگر به آن نیاز نداریم (اختیاری: در Settings → Danger می‌توانید کل حساب را هم Delete کنید).

### ۱-۲) اصلاح فوری redirect دامنه در Vercel

این کار را همین حالا انجام دهید تا اپ روی آدرس `vercel.app` قابل بازدید شود (حتی قبل از استقرار تمیز):

1. **https://vercel.com** → ورود → پروژه `gas-dt-portfolio`.
2. **Settings → Domains**.
3. روی ردیف `gas-dt-portfolio.vercel.app` → دکمه **Edit**.
4. گزینه انتخابی را از **Redirect to Another Domain** به **Connect to an environment** تغییر دهید → محیط **Production** → **Save**.
5. آزمون: `https://gas-dt-portfolio.vercel.app` را باز کنید → دیگر نباید به `gasdt.app` پرت شود. ✅

### ۱-۳) (پیشنهادی برای شروع کاملاً تمیز) حذف پروژه Vercel و Import مجدد

اگر می‌خواهید همه‌چیز از صفر باشد (توصیه‌شده):

1. در همان پروژه: **Settings → General** → پایین صفحه → بخش **Delete Project** → دکمه **Remove** → تأیید با تایپ نام پروژه.
2. به **گام ۴** بروید و پروژه را دوباره از GitHub Import کنید — بدون هیچ بقایای تنظیمات قبلی.

> اگر حذف نمی‌کنید، به گام ۴ فقط برای بازبینی envها بروید.

## گام ۲ — ساخت دیتابیس رایگان در Supabase (۷ دقیقه)

1. مرورگر: **https://supabase.com** → **Sign up** (یا **Start your project**) → با **GitHub** وارد شوید → Authorize.
2. اگر سازمان خواست: **New personal account** / نام دلخواه → Skip بقیه سؤال‌ها.
3. دکمه **New project**:
   - **Name:** `gasdt`
   - **Database Password:** دکمه **Generate a password** → ⚠️ **این رمز را در Notepad ذخیره کنید** (بازهم دیده نمی‌شود مگر Reset شود)
   - **Region:** **West EU (London)** یا **Central EU (Frankfurt)** — هر دو خوب‌اند؛ فرانکفورت را انتخاب کنید
   - Plan: **Free** ($0) — کارت بانکی نمی‌خواهد
4. **Create new project** → ۱-۲ دقیقه صبر (Initializing).
5. وقتی پروژه فعال شد، از منوی کناری: **Connect** (دکمه بالای صفحه) یا **Project Settings → Database → Connection string**:
   - گزینه **Session pooler** را انتخاب کنید (پورت **5432**).
   - رشته‌ای شبیه زیر را کپی کنید:
     ```
     postgresql://postgres.abcdefghij:رمزتان@aws-0-eu-central-1.pooler.supabase.com:5432/postgres?sslmode=require
     ```
   - به‌جای `رمزتان` همان رمز ذخیره‌شدهٔ مرحله ۳ می‌نشیند (معمولاً خود رشته کامل است).
6. این رشته را در Notepad با برچسب `DATABASE_URL` ذخیره کنید.

> 💡 چرا Session pooler (5432)؟ چون با Prisma بدون هیچ پارامتر اضافه‌ای سازگار است. (گزینه Transaction pooler پورت 6543 هم هست ولی نیازمند پارامتر `pgbouncer=true` است — لازم نیست.)
> ⚠️ اتصال مستقیم `db.<ref>.supabase.co` (پورت 5432 بدون pooler) IPv6 است و با Vercel کار نمی‌کند — **حتماً از رشته pooler استفاده کنید.**

✅ **نتیجه:** دیتابیس PostgreSQL خالی، رایگان، بدون کارت بانکی و **از ایران قابل مدیریت**.

## گام ۴ — استقرار تمیز در Vercel (۱۰ دقیقه)

1. **https://vercel.com** → داشبورد → **Add New… → Project**.
2. اگر `GasDTPortfolio` در لیست نبود: **Adjust GitHub App Permissions** → دسترسی به ریپو بدهید → Install → برگردید.
3. کنار `GasDTPortfolio` دکمه **Import**.
4. صفحه **Configure Project**:
   - Framework Preset: خودکار «Next.js» — دست نزنید.
   - Build/Output/Install Commands: پیش‌فرض (فایل `vercel.json` ریپو دستور build صحیح را تزریق می‌کند).
5. بخش **Environment Variables** — **سه ردیف** اضافه کنید (هر بار Name و Value و **Add**):

   | Name | Value |
   |---|---|
   | `DATABASE_URL` | رشته Supabase از گام ۲ (کپی دقیق، بدون فاصله ابتدا/انتها) |
   | `CRON_SECRET` | رشته تصادفی ۱ |
   | `BOOTSTRAP_TOKEN` | رشته تصادفی ۲ |

6. قبل از Deploy: تب **Settings → Functions → Function Region** → گزینه **Frankfurt (fra1)** را انتخاب کنید تا اپ نزدیک دیتابیس باشد (روی Hobby هم رایگان است). سپس برگردید.
7. دکمه **Deploy** → لاگ زنده: Installing → prisma generate → next build → Deploying (~۲ تا ۴ دقیقه).
8. موفق: تیک سبز + «Congratulations!» → **Continue to Dashboard** → دکمه **Visit** → آدرس اپ (مثل `https://gas-dt-portfolio.vercel.app`) — در Notepad ذخیره کنید.

> ❌ اگر build خطا داد: تب **Deployments** → نسخه قرمز → **Building** → متن خطا را کپی و برای من بفرستید.
> ℹ️ در این لحظه اپ بالا می‌آید ولی چون دیتابیس خالی است ورود جواب نمی‌دهد — **طبیعی است**؛ گام بعدی.

## گام ۵ — راه‌اندازی اولیه + تغییر رمزها (۵ دقیقه)

### ۵-۱) فراخوانی bootstrap (فقط یک‌بار در عمر محیط)

این آدرس را در مرورگر باز کنید (آدرس اپ + `/api/system/bootstrap?token=` + مقدار BOOTSTRAP_TOKEN):

```
https://APP.vercel.app/api/system/bootstrap?token=BOOTSTRAP_TOKEN
```

پاسخ موفق — JSON شبیه:

```json
{
  "ok": true,
  "ddl": { "executed": 67, "skipped": 0 },
  "seed": { "counts": { "users": 8, "actions": 37, "roles": 16, "kpis": 8, "settings": 32, "documents": ... } },
  "demoCredentials": { "users": ["admin","auditor","council","itc.liaison","itc.mgr","sec.admin","secretary","viewer"], "password": "Nigc@1405", ... },
  "nextSteps": [...]
}
```

**همین حالا این JSON را کامل کپی و ذخیره کنید** — رمزهای اولیه فقط همین یک‌بار نمایش داده می‌شود.

### ۵-۲) نخستین ورود و تغییر فوری رمزها

1. آدرس اپ را باز کنید → صفحه ورود فارسی.
2. نام کاربری `admin` / رمز `Nigc@1405` → ورود (دسترسی کامل).
3. ماژول **مدیریت کاربران** → برای **هر ۸ کاربر** نمونه → ویرایش → رمز قوی جدید + نام کامل واقعی. الگوی پیشنهادی: `جمله+عدد+نماد` مثل `Gaz1405!Hokmrani`.
4. خروج و ورود مجدد با رمز جدید → تأیید.

### ۵-۳) قفل‌کردن مسیر bootstrap (بسیار مهم)

1. Vercel → پروژه → **Settings → Environment Variables** → ردیف `BOOTSTRAP_TOKEN` → ⋯ → **Remove**.
2. تب **Deployments** → آخرین deploy → ⋯ → **Redeploy** → Confirm.
3. آزمون: آدرس bootstrap را دوباره باز کنید → باید پیام 403 «غیرفعال» بدهد. ✅

## گام ۶ — فعال‌سازی موتور یادآور (۵ دقیقه) ⚠️ برای Supabase حیاتی است

> 🔴 **چرا حیاتی؟** پروژه رایگان Supabase پس از ۱ هفته بی‌کاری pause می‌شود. تیک هر ۵ دقیقه این جاب، دیتابیس را همیشه فعال نگه می‌دارد.

1. **https://cron-job.org** → Sign up (رایگان) → تأیید ایمیل → ورود.
2. **Cronjobs** → **+ CREATE CRONJOB**:
   - **Title:** `NIGC-DTG reminder tick`
   - **URL:**
     ```
     https://APP.vercel.app/api/system/cron-tick?key=CRON_SECRET
     ```
   - **Execution Schedule:** **Every 5 minutes**
   - **Save** → وضعیت جاب **فعال (Active)** باشد.
3. **آزمون فوری:** **Run now** → تاریخچه اجرا → **Status: 200** و بدنه `"ok": true`.
4. **اعلان شکست:** تنظیمات جاب → notify on failure را با ایمیل خود فعال کنید (اگر جاب بایستد و دیتابیس بخوابد، فوراً باخبر می‌شوید).
5. **تأیید از داخل سامانه:** ورود با `admin` → تنظیمات → پنل **سلامت سامانه** → `scheduler.alive: true` و اجرای تازه.

> 🔒 اگر رابط cron-job.org امکان هدر سفارشی داشت، امن‌تر است کلید را از URL حذف و در بخش Advanced هدر `Authorization: Bearer CRON_SECRET` بگذارید.

## گام ۸ — اصلاح دامنه `gasdt.app` (۱۰ دقیقه)

وضعیت فعلی شما: دامنه **Invalid Configuration** + redirect معکوس روی `vercel.app`. ترتیب درست:

### ۸-۱) تنظیم DNS نزد ارائه‌دهنده دامنه

در پنل جایی که `gasdt.app` را تهیه کرده‌اید، رکوردهای DNS را دقیقاً این‌گونه ثبت کنید:

| نوع | نام/Host | مقدار (Value) |
|---|---|---|
| `A` | `@` (یا خالی) | `76.76.21.21` |
| `CNAME` | `www` | `cname.vercel-dns.com` |

- رکوردهای دیگری که A یا AAAA روی `@` هستند را حذف کنید (تداخل ایجاد می‌کنند).
- TTL پیش‌فرض بماند؛ اعمال DNS از چند دقیقه تا چند ساعت طول می‌کشد.

### ۸-۲) تأیید در Vercel

1. Vercel → پروژه → **Settings → Domains**.
2. مطمئن شوید `gas-dt-portfolio.vercel.app` روی **Connect to an environment: Production** است (کار گام ۱-۲).
3. کنار `gasdt.app` دکمه **Refresh** → صبر کنید تا **Valid Configuration** (تیک سبز) شود؛ گواهی SSL خودکار صادر می‌شود.
4. حالا اگر می‌خواهید آدرس اصلی `gasdt.app` باشد: روی `gas-dt-portfolio.vercel.app` → **Edit** → **Redirect to Another Domain** → `gasdt.app` → Save. (جهت redirect فقط یک‌طرفه و پس از Valid شدن دامنه اصلی — برعکسِ تنظیم فعلی که سایت را می‌شکند.)
5. در cron-job.org و بوکمارک‌ها، آدرس نهایی را جایگزین کنید.

> 💡 مزیت دامنه اختصاصی: آدرس‌های `*.vercel.app` گاهی در ایران محدود/کند می‌شوند؛ دامنه شخصی معمولاً پایدارتر است.

- **بکاپ (Supabase Free بکاپ خودکار ندارد):** هر هفته در Supabase → **SQL Editor** → `select * from "ActionItem"` و جدول‌های مهم → خروجی CSV؛ یا کل دیتابیس با دستور `pg_dump "$DATABASE_URL" > backup.sql` روی هر سیستم لینوکسی.
- **پایش مصرف:** Vercel → Usage؛ Supabase → Reports/Usage. پلن رایگان برای این سامانه به‌وفور کافی است.
- **رفتار طبیعی Supabase:** با تیک ۵دقیقه‌ای cron، پروژه هرگز pause نمی‌شود؛ اگر روزی جاب متوقف شد، در داشبورد Supabase دکمه **Restore** پروژه را دوباره فعال می‌کند.

## تفاوت‌های صادقانه نسخه ابری

| قابلیت | وضعیت روی ابر |
|---|---|
| دستیار هوشمند (AI) | **غیرفعال** (ارائه‌دهنده فعلی وابسته به زیرساخت توسعه است) — پیام شفاف نمایش داده می‌شود؛ هسته سامانه کامل کار می‌کند |
| ایمیل واقعی | اعلان‌ها در **صف EmailOutbox** ثبت و در پنل سلامت دیده می‌شوند؛ ارسال واقعی نیازمند SMTP سازمانی (جعل ارسال نمی‌شود)؛ اعلان درون‌برنامه‌ای فعال است |
| محدودیت نرخ | به‌ازای هر نمونه سرورلس جدا شمرده می‌شود — کفایت می‌کند |

## عیب‌یابی سریع

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| باز کردن اپ → پرت به `gasdt.app` و خطا | redirect معکوس دامنه | گام ۱-۲: Edit دامنه `vercel.app` → Connect to Production |
| `gasdt.app`: Invalid Configuration | DNS ناتمام | گام ۸-۱: رکورد A و CNAME → Refresh |
| باز کردن اپ → صفحه لاگین Vercel | Deployment Protection | Settings → Deployment Protection → Standard Protection را **Disabled** کنید |
| Build failed در Vercel | خطای محیط/وابستگی | متن خطا در Deployments → Building → برای من بفرستید |
| bootstrap: `DDL_FAILED` / timeout | رشته اتصال غلط | `DATABASE_URL` باید از **Supabase Session pooler (پورت 5432، host شامل `pooler.supabase.com`)** با `?sslmode=require` باشد؛ بعد از اصلاح env → **Redeploy** |
| bootstrap: `alreadyBootstrapped` | قبلاً اجرا شده | طبیعی — ادامه دهید |
| ورود نمی‌شود | رمز تغییر کرده / دیتابیس خالی | اگر دیتابیس خالی: گام ۵؛ اگر رمز: ریست با مدیر ادمین |
| خطای `P1001` (can't reach database) | استفاده از host غیر-pooler یا پروژه Supabase در حالت pause | رشته pooler (5432) را بگذارید؛ در Supabase پروژه را Restore کنید → Redeploy |
| cron-tick: `403` | CRON_SECRET نادرست/حذف | مقدار را در Environment Variables چک کنید → **Redeploy** |
| پاسخ‌ها کند | فاصله ریجن اپ و دیتابیس | Function Region و Supabase Region هر دو فرانکفورت |
| یادآورها نمی‌آیند / پروژه Supabase خوابید | جاب cron متوقف شده | تاریخچه cron-job.org + پنل سلامت سامانه؛ Restore پروژه |
| تغییر env اثر نکرد | envها فقط با redeploy اعمال می‌شوند | Deployments → ⋯ → Redeploy |
