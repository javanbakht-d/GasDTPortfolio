# راهنمای گام‌به‌گام استقرار رایگان ابری

**هدف:** اجرای سامانه NIGC-DTG روی بستر ابری **کاملاً رایگان** و دادن دسترسی به کاربران، بدون نیاز به هیچ ابزار یا سروری روی سیستم خودتان — فقط مرورگر.

**معماری انتخابی:**

| جزء | سرویس | چرا |
|---|---|---|
| اپلیکیشن Next.js | **Vercel** (پلن Hobby رایگان) | سازنده Next.js است؛ پشتیبانی بومی و استقرار خودکار از GitHub |
| دیتابیس PostgreSQL | **Neon** (پلن رایگان — ۰٫۵ گیگابایت) | سرورلس، سازگار رسمی با Prisma، بدون خواب‌افتادگی دائمی |
| موتور یادآور | **cron-job.org** (رایگان) | هر ۵ دقیقه تیک زمان‌بند را فرامی‌خواند — یادآوری مستقل از مرورگر کاربران |

> ⚠️ **قبل از شروع — دو نکته صادقانه:**
> 1. ریپوی فعلی **عمومی (Public)** است. داده‌های نمونه و مستندات همگانی می‌شود. اگر می‌خواهید خصوصی باشد: در GitHub → Settings → پایین صفحه → Danger Zone → Change visibility → Private. (استقرار با ریپوی خصوصی هم در Vercel رایگان است.)
> 2. دسترسی به سرویس‌های آمریکایی از داخل ایران ممکن است نیازمند تغییر IP باشد و دامنه `vercel.app` گاهی محدود است. اگر برای کاربران مشکل شد، راه‌حل: اتصال یک **دامنه اختصاصی** (گام ۸).

---

## گام ۱ — ساخت دیتابیس رایگان در Neon

1. به **https://neon.tech** بروید و **Sign up** → گزینه **Continue with GitHub** (با همان اکانت GitHub خودتان).
2. پس از ورود، روی **Create project** کلیک کنید:
   - Project name: `gasdt`
   - PostgreSQL version: 16 (پیش‌فرض)
   - Cloud & Region: **AWS** و ترجیحاً **US East 1** (نزدیک‌ترین ریجن به سرور پیش‌فرض Vercel — سرعت بهتر)
3. پس از ساخت، داشبورد یک **Connection string** به شکل زیر نشان می‌دهد — آن را با دکمه کپی بردارید و در جایی امن ذخیره کنید (در گام ۳ لازم دارید):
   ```
   postgresql://user:password@ep-xxxx-pooler.region.aws.neon.tech/neondb?sslmode=require
   ```
   > اگر رشته با `-pooler` نبود، از منوی Connect گزینه **Pooled connection** را انتخاب کنید.

✅ **پایان گام ۱** — یک دیتابیس PostgreSQL خالی رایگان دارید.

---

## گام ۲ — توکن‌های امن بسازید

دو رشته تصادفی بسازید (مثل رمز قوی، ۳۲ کاراکتر به بالا):

- `CRON_SECRET` — کلید فراخوانی موتور یادآور
- `BOOTSTRAP_TOKEN` — کلید یک‌بارِ راه‌اندازی اولیه

**ساخت آسان:** در مرورگر کلید **F12** را بزنید → تب **Console** → این خط را اجرا کنید:
```js
crypto.randomUUID().replace(/-/g,"") + crypto.randomUUID().replace(/-/g,"")
```
دو بار اجرا کنید و خروجی‌ها را ذخیره کنید.

---

## گام ۳ — استقرار در Vercel

1. به **https://vercel.com** بروید → **Sign up / Log in** → **Continue with GitHub** و اجازه دسترسی بدهید.
2. از داشبورد: **Add New… → Project**
3. در لیست ریپوها، کنار `GasDTPortfolio` روی **Import** بزنید.
4. در صفحه تنظیمات، بخش **Environment Variables** این سه متغیر را اضافه کنید (هر کدام: Name و Value):

   | Name | Value |
   |---|---|
   | `DATABASE_URL` | رشته اتصال Neon از گام ۱ |
   | `CRON_SECRET` | مقدار تصادفی گام ۲ |
   | `BOOTSTRAP_TOKEN` | مقدار تصادفی دیگر گام ۲ |

5. بقیه تنظیمات را دست نزنید (Vercel خودش تشخیص می‌دهد Next.js است) → **Deploy** را بزنید.
6. ۲ تا ۴ دقیقه صبر کنید تا صفحه گرین‌شو «Congratulations» بیاید. آدرس اپ شما چیزی شبیه `https://gasdtportfolio.vercel.app` است (دکمه **Visit**).

> اگر Build خطا داد: به تب **Deployments** → روی deploy خطادار → **Building** → متن خطا را برای من بفرستید.

✅ **پایان گام ۳** — اپ روی ابر اجرا می‌شود ولی هنوز دیتابیس خالی است.

---

## گام ۴ — راه‌اندازی اولیه (ساخت جداول + داده‌ها) — فقط یک‌بار

در مرورگر این آدرس را باز کنید (به‌جای `APP` آدرس اپ و به‌جای `TOKEN` مقدار BOOTSTRAP_TOKEN):

```
https://APP.vercel.app/api/system/bootstrap?token=TOKEN
```

پاسخ موفق چنین است:

```json
{ "ok": true, "ddl": { "executed": 67 }, "seed": { "users": 8, "actions": 37, ... },
  "demoCredentials": { "users": ["admin", ...], "password": "Nigc@1405", ... } }
```

**فوری این سه کار را بکنید:**
1. پاسخ JSON را کپی و در جایی امن ذخیره کنید (رمزهای اولیه فقط همین یک‌بار نمایش داده می‌شود).
2. بلافاصله به اپ وارد شوید: کاربر `admin` / رمز `Nigc@1405` → ماژول **مدیریت کاربران** → رمز همه ۸ کاربر نمونه را تغییر دهید.
3. در Vercel → Project → **Settings → Environment Variables** → متغیر `BOOTSTRAP_TOKEN` را **Delete** کنید → تب **Deployments** → روی آخرین deploy ⋯ → **Redeploy** (تا مسیر bootstrap برای همیشه قفل شود).

✅ **پایان گام ۴** — سامانه کامل با ۳۷ گام سند ابلاغی، ۱۶ نقش، ۸ کاربر و همه ماژول‌ها آماده است.

---

## گام ۵ — فعال‌سازی موتور یادآور (زمان‌بند بیرونی)

روی ابر، چرخه یادآوری با سرویس رایگان cron-job.org کار می‌کند:

1. به **https://cron-job.org** بروید → ثبت‌نام رایگان (Sign up).
2. داشبورد → **Cronjobs → Create cronjob**:
   - Title: `NIGC-DTG reminder tick`
   - URL: `https://APP.vercel.app/api/system/cron-tick?key=CRON_SECRET` (به‌جای CRON_SECRET مقدار گام ۲)
   - Schedule / اجرا: **Every 5 minutes** (یا دستی: `*/5 * * * *`)
   - گزینه Notifications (اختیاری): اگر اجرای تیک شکست بخورد ایمیل بدهد
3. **Save** → سپس دکمه **Start** (فعال‌سازی) را بزنید.
4. **آزمون:** روی job دکمه **Run now** را بزنید → در جزئیات اجرا باید پاسخ `200` و بدنه `"ok": true` ببینید.

**تأیید سلامت از داخل سامانه:** با `admin` وارد اپ شوید → ماژول تنظیمات → بخش **سلامت و قابلیت اعتماد دستیار** → باید آخرین اجرای زمان‌بند تازه و `alive: true` باشد.

> 🔒 امن‌تر: به‌جای `?key=` در URL، در تنظیمات Advanced همان job، هدر `Authorization: Bearer CRON_SECRET` را اضافه کنید و کلید را از URL حذف کنید.

✅ **پایان گام ۵** — یادآوری‌ها بدون باز بودن مرورگر هیچ‌کس کار می‌کنند.

## گام ۶ — صحت‌سنجی نهایی (چک‌لیست ۸ موردی)

| # | آزمون | روش | نتیجه مورد انتظار |
|---|---|---|---|
| ۱ | اپ بالا آمده | باز کردن آدرس اپ | صفحه ورود فارسی RTL |
| ۲ | ورود ادمین | `admin` + رمز جدید | داشبورد با داده‌های ۳۷ گام |
| ۳ | داده‌ها کامل | ماژول اقدامات | ۳۷ اقدام با سررسید و منبع |
| ۴ | تیک زمان‌بند | Run now در cron-job.org | پاسخ 200 + `ok:true` |
| ۵ | سلامت دستیار | پنل سلامت در تنظیمات | `scheduler.alive: true` |
| ۶ | جلوگیری از تیک تکراری | دو بار پشت‌هم Run now | بار دوم `skipped` یا بدون اعلان تکراری |
| ۷ | کنترل دسترسی | ورود با کاربر `viewer` | فقط مشاهده — بدون دکمه‌های مدیریتی |
| ۸ | موبایل | باز کردن اپ با گوشی | چیدمان سالم و ریسپانسیو |

## گام ۷ — نگهداری جاری

- **به‌روزرسانی اپ:** هر تغییری که در سندباکس انجام شود و به GitHub push شود، Vercel **خودکار** deploy می‌کند. (برای push بعدی، توکن جدید به من بدهید.)
- **بکاپ دیتابیس:** داشبورد Neon → Branch/Restore — از دیتابیس هر زمان نسخه لحظه‌ای بسازید. (توصیه: هفته‌ای یک‌بار.)
- **مصرف پلن رایگان Neon:** ۰٫۵ گیگابایت فضای و ~۱۹۰ ساعت فعال‌سازی در ماه — برای این سامانه بسیار کافی است. پس از ۵ دقیقه بی‌استفاده، دیتابیس «می‌خوابد» و اولین درخواست بعدی ۱ تا ۲ ثانیه کندتر است — طبیعی است.
- **محدودیت‌های پلن رایگان Vercel:** ترافیک مجاز پورتفولیو را کاملاً پوشش می‌دهد؛ اجرای توابع تا ۶۰ ثانیه.

## چیزهایی که در نسخه ابری فعلاً متفاوت است (شفاف‌سازی صادقانه)

| قابلیت | وضعیت روی ابر |
|---|---|
| دستیار هوشمند (AI) | **غیرفعال** — ارائه‌دهنده فعلی به زیرساخت سندباکس وابسته است. هسته سامانه بدون آن کامل کار می‌کند؛ پیام شفاف «غیرفعال» نمایش داده می‌شود. فعال‌سازی آینده نیازمند اتصال یک سرویس مدل زبانی است. |
| ارسال ایمیل واقعی | اعلان‌ها در **صف (EmailOutbox)** ثبت می‌شوند و در پنل سلامت دیده می‌شوند؛ ارسال واقعی نیازمند پیکربندی SMTP سازمانی است (جعل ارسال نمی‌شود). اعلان‌های درون‌برنامه‌ای فعال‌اند. |
| محدودیت نرخ (rate limit) | در هر نمونه سرورلس جداگانه شمرده می‌شود — سخت‌گیرانه‌تر از حالت لوکال نیست، کافی است. |

## گام ۸ (اختیاری) — دامنه اختصاصی

اگر `vercel.app` برای کاربران محدود بود: در Vercel → Project → **Settings → Domains** → یک دامنه (مثلاً `gasdt.yourdomain.ir`) اضافه کنید و طبق راهنمای همان صفحه، رکورد DNS را در پنل دامنه ثبت کنید. SSL خودکار صادر می‌شود.

## عیب‌یابی سریع

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| Build failed در Vercel | خطای محیط/وابستگی | متن خطا در Deployments → Building → برای من بفرستید |
| `500` روی bootstrap با `DDL_FAILED` | رشته اتصال غلط یا دیتابیس آماده نیست | DATABASE_URL را دوباره از Neon چک کنید (باید `?sslmode=require` داشته باشد) |
| bootstrap می‌گوید `alreadyBootstrapped` | قبلاً اجرا شده | طبیعی — به گام بعد بروید |
| cron-tick پاسخ `403` | CRON_SECRET اشتباه یا حذف‌شده | مقدار را در Vercel → Environment Variables چک و Redeploy کنید |
| پاسخ‌ها کند (۱-۲ ثانیه) | خواب Neon پس از بی‌استفادگی | طبیعی پلن رایگان |
| یادآورها نمی‌آیند | cron-job.org متوقف شده | تاریخچه اجرای job و پنل سلامت سامانه را چک کنید |
