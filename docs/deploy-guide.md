# راهنمای کامل و گام‌به‌گام استقرار رایگان ابری — NIGC-DTG

**هدف:** اجرای سامانه روی بستر ابری **کاملاً رایگان** و دادن دسترسی به کاربران، بدون نیاز به سرور یا ابزار خاص روی سیستم شما — فقط مرورگر.

**زمان کل: حدود ۳۰ تا ۴۵ دقیقه**

| گام | کار | زمان |
|---|---|---|
| ۰ | پیش‌نیازها و آماده‌سازی | ۲ دقیقه |
| ۱ | ساخت دیتابیس رایگان در Neon | ۵ دقیقه |
| ۲ | ساخت دو توکن امن | ۲ دقیقه |
| ۳ | استقرار در Vercel | ۱۰ دقیقه |
| ۴ | راه‌اندازی اولیه (bootstrap) + تغییر رمزها | ۵ دقیقه |
| ۵ | فعال‌سازی موتور یادآور (cron-job.org) | ۵ دقیقه |
| ۶ | صحت‌سنجی نهایی (چک‌لیست) | ۵ دقیقه |
| ۷ | دعوت کاربران و نگهداری | — |
| ۸ | (اختیاری) دامنه اختصاصی | ۱۰ دقیقه |

**معماری انتخابی:**

| جزء | سرویس | چرا |
|---|---|---|
| اپلیکیشن Next.js | **Vercel** (پلن Hobby رایگان) | سازنده Next.js؛ استقرار خودکار از GitHub |
| دیتابیس PostgreSQL | **Neon** (پلن رایگان — ۰٫۵ گیگابایت) | سرورلس، سازگار رسمی با Prisma |
| موتور یادآور | **cron-job.org** (رایگان) | هر ۵ دقیقه تیک — یادآوری مستقل از مرورگر کاربران |

> ⚠️ **دو نکته صادقانه قبل از شروع:**
> 1. ریپوی فعلی **عمومی (Public)** است. اگر می‌خواهید خصوصی باشد: GitHub → Settings → پایین صفحه → Danger Zone → Change visibility → Private. استقرار با ریپوی خصوصی هم رایگان است.
> 2. دسترسی به سرویس‌های آمریکایی از داخل ایران ممکن است نیازمند تغییر IP باشد و دامنه `vercel.app` گاهی محدود است. راه‌حل در گام ۸ (دامنه اختصاصی).

## گام ۱ — ساخت دیتابیس رایگان در Neon (۵ دقیقه)

1. مرورگر: **https://neon.tech** را باز کنید.
2. بالا-راست **Sign Up** → گزینه **Continue with GitHub**.
3. صفحه GitHub باز می‌شود → دکمه **Authorize NEON** (یا Authorize neon.tech) را بزنید.
4. اولین ورود: چند سؤال معرفی می‌پرسد — با **Skip** رد شوید.
5. در داشبورد دکمه **Create project** (یا New Project):
   - **Project name:** `gasdt`
   - **PostgreSQL version:** 16 (پیش‌فرض)
   - **Cloud & Region:** AWS و **US East 1** (نزدیک به ریجن پیش‌فرض Vercel → سریع‌ترین پاسخ)
6. **Create** را بزنید. چند ثانیه بعد دیتابیس ساخته می‌شود.
7. صفحه‌ای به نام **Connect** باز می‌شود:
   - مطمئن شوید حالت **Pooled connection** فعال است (سوئیچ یا تب مخصوص آن).
   - رشته‌ای شبیه زیر را با دکمه کپی بردارید:
     ```
     postgresql://neondb_owner:XXXXXXXX@ep-xxxx-name-a1b2c3d4-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require
     ```
8. این رشته را در Notepad با برچسب `DATABASE_URL` ذخیره کنید.

> 💡 اگر پنجره Connect را بستید: در داشبورد پروژه دکمه **Connect** (بالای صفحه) دوباره آن را باز می‌کند.

✅ **نتیجه:** دیتابیس PostgreSQL خالی، رایگان و همیشه‌روشن (با خواب سبک).

| `BOOTSTRAP_TOKEN` | (رشته تصادفی ۲) | گام ۲ |

## گام ۳ — استقرار در Vercel (۱۰ دقیقه)

1. **https://vercel.com** → **Sign Up** → **Continue with GitHub** → Authorize.
2. سؤال ساخت تیم/پلن: **Personal / Hobby (رایگان)** را انتخاب یا Skip کنید.
3. داشبورد → کنار عنوان Projects دکمه **Add New… → Project**.
4. اگر `GasDTPortfolio` در لیست نبود: **Adjust GitHub App Permissions** → دسترسی به این ریپو بدهید (All یا Selected) → Install → به Vercel برگردید.
5. کنار `GasDTPortfolio` دکمه **Import**.
6. صفحه **Configure Project**:
   - Framework Preset: خودکار «Next.js» تشخیص داده می‌شود — دست نزنید.
   - Build/Output/Install Commands: پیش‌فرض (فایل `vercel.json` ریپو دستور build صحیح را تزریق می‌کند).
7. بخش **Environment Variables** را باز کنید و **سه ردیف** اضافه کنید (هر بار: Name و Value و **Add**):

   | Name | Value |
   |---|---|
   | `DATABASE_URL` | رشته Neon از گام ۱ (کپی دقیق، بدون فاصله ابتدا/انتها) |
   | `CRON_SECRET` | رشته تصادفی ۱ |
   | `BOOTSTRAP_TOKEN` | رشته تصادفی ۲ |

   > Environments هر متغیر روی پیش‌فرض (همه) بماند.
8. دکمه **Deploy** را بزنید.
9. صفحه build با لاگ زنده — مراحل: Installing → prisma generate → next build → Deploying (~۲ تا ۴ دقیقه).
10. موفق: تیک سبز + «Congratulations!». دکمه **Continue to Dashboard** → دکمه **Visit** → آدرس اپ شما (مثلاً `https://gasdtportfolio.vercel.app`). این آدرس را در Notepad ذخیره کنید.

> ❌ اگر build خطا داد: تب **Deployments** → روی نسخه قرمز → **Building** → متن خطا را کپی و برای من بفرستید.
> ℹ️ در این لحظه اپ بالا می‌آید ولی چون دیتابیس خالی است ورود جواب نمی‌دهد — **طبیعی است**؛ گام بعدی را انجام دهید.

## گام ۴ — راه‌اندازی اولیه + تغییر رمزها (۵ دقیقه)

### ۴-۱) فراخوانی bootstrap (فقط یک‌بار در عمر محیط)

این آدرس را در مرورگر باز کنید (آدرس اپ + `/api/system/bootstrap?token=` + مقدار BOOTSTRAP_TOKEN):

```
https://APP.vercel.app/api/system/bootstrap?token=BOOTSTRAP_TOKEN
```

پاسخ موفق — JSON شبیه:

```json
{
  "ok": true,
  "ddl": { "executed": 67, "skipped": 0 },
  "seed": { "counts": { "users": 8, "actions": 37, "roles": 16, "kpis": 8, "settings": 32, "documents": ... } },
  "demoCredentials": { "users": ["admin","auditor","council","itc.liaison","itc.mgr","sec.admin","secretary","viewer"], "password": "Nigc@1405", ... },
  "nextSteps": [...]
}
```

**همین حالا این JSON را کامل کپی و ذخیره کنید** — رمزهای اولیه فقط همین یک‌بار نمایش داده می‌شود.

### ۴-۲) نخستین ورود و تغییر فوری رمزها

1. آدرس اپ را باز کنید → صفحه ورود فارسی.
2. نام کاربری `admin` / رمز `Nigc@1405` → ورود (این کاربر دسترسی کامل دارد).
3. ماژول **مدیریت کاربران** → برای **هر ۸ کاربر** نمونه → ویرایش → رمز قوی جدید + نام کامل واقعی. پیشنهاد الگوی رمز: `جمله+عدد+نماد` مثل `Gaz1405!Hokmrani`.
4. خروج و ورود مجدد با رمز جدید → تأیید.

### ۴-۳) قفل‌کردن مسیر bootstrap (بسیار مهم)

1. Vercel → پروژه → **Settings → Environment Variables** → ردیف `BOOTSTRAP_TOKEN` → ⋯ → **Remove**.
2. تب **Deployments** → روی آخرین deploy → ⋯ → **Redeploy** → Confirm.
3. آزمون: آدرس bootstrap را دوباره باز کنید → باید پیام 403 «غیرفعال» بدهد. ✅

## گام ۵ — فعال‌سازی موتور یادآور (۵ دقیقه)

1. **https://cron-job.org** → Sign up (رایگان) → ایمیل تأیید را چک کنید → ورود.
2. داشبورد → **Cronjobs** → دکمه **+ CREATE CRONJOB**:
   - **Title:** `NIGC-DTG reminder tick`
   - **URL:**
     ```
     https://APP.vercel.app/api/system/cron-tick?key=CRON_SECRET
     ```
   - **Execution Schedule:** گزینه **Every 5 minutes** را انتخاب کنید.
   - **Save** → در صفحه جزئیات، وضعیت جاب را **فعال (Active/Start)** کنید.
3. **آزمون فوری:** دکمه **Run now** → بخش تاریخچه اجرا → باید **Status: 200** و بدنه‌ای با `"ok": true` ببینید.
4. **اعلان شکست (پیشنهادی):** در تنظیمات جاب/اکانت، گزینه notify on failure را با ایمیل خود فعال کنید.
5. **تأیید از داخل سامانه:** با `admin` وارد اپ شوید → تنظیمات → بخش **سلامت و قابلیت اعتماد دستیار** → باید `scheduler.alive: true` و آخرین اجرای تازه باشد.

> 🔒 اگر رابط cron-job.org امکان هدر سفارشی داشت، امن‌تر است کلید را از URL حذف و در بخش Advanced هدر `Authorization: Bearer CRON_SECRET` بگذارید.

## گام ۷ — دعوت کاربران و نگهداری

- **دعوت:** فقط آدرس اپ را بدهید؛ هر کاربر با نام کاربری خودش وارد می‌شود. نقش‌های نمونه: `sec.admin` (مدیر دبیرخانه)، `secretary` (دبیر شورا)، `council` (عضو شورا)، `itc.mgr` (مدیر واحد)، `itc.liaison` (رابط تحول)، `auditor` (ممیز)، `viewer` (مشاهده‌گر).
- **آپدیت اپ:** هر push جدید به GitHub → Vercel خودکار deploy می‌کند.
- **بکاپ:** داشبورد Neon → بخش Branch/Restore — هر هفته یک Branch از وضعیت جاری بسازید (نسخه لحظه‌ای رایگان). در صورت اشتباه: Branch را بررسی/بازیابی کنید.
- **پایش مصرف:** Vercel → Usage؛ Neon → Metrics. پلن رایگان برای پورتفولیو به‌وفور کافی است.
- **رفتار طبیعی:** پس از ۵ دقیقه بی‌استفادگی، Neon «می‌خوابد»؛ اولین درخواست بعدی ۱-۲ ثانیه کندتر است.

## تفاوت‌های صادقانه نسخه ابری

| قابلیت | وضعیت روی ابر |
|---|---|
| دستیار هوشمند (AI) | **غیرفعال** (ارائه‌دهنده فعلی وابسته به زیرساخت توسعه است) — پیام شفاف نمایش داده می‌شود؛ هسته سامانه کامل کار می‌کند |
| ایمیل واقعی | اعلان‌ها در **صف EmailOutbox** ثبت و در پنل سلامت دیده می‌شوند؛ ارسال واقعی نیازمند SMTP سازمانی (جعل ارسال نمی‌شود)؛ اعلان درون‌برنامه‌ای فعال است |
| محدودیت نرخ | به‌ازای هر نمونه سرورلس جدا شمرده می‌شود — کفایت می‌کند |

## گام ۸ (اختیاری) — دامنه اختصاصی

اگر `vercel.app` برای کاربران محدود بود:

1. Vercel → پروژه → **Settings → Domains** → **Add** → مثلاً `gasdt.yourdomain.ir`.
2. Vercel یک رکورد (معمولاً CNAME به `cname.vercel-dns.com`) نشان می‌دهد → در پنل دامنه‌تان همان رکورد DNS را ثبت کنید.
3. صبر برای تأیید (دقایقی) → SSL خودکار صادر می‌شود.
4. در cron-job.org و بوکمارک‌ها، آدرس دامنه جدید را جایگزین کنید.

## عیب‌یابی سریع

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| باز کردن اپ → صفحه لاگین Vercel | Deployment Protection | Settings → Deployment Protection → Standard Protection را **Disabled** کنید |
| Build failed در Vercel | خطای محیط/وابستگی | متن خطا در Deployments → Building → برای من بفرستید |
| bootstrap: `DDL_FAILED` | رشته اتصال غلط | `DATABASE_URL` باید از Neon با `-pooler` و `?sslmode=require` باشد؛ بعد از اصلاح env → **Redeploy** |
| bootstrap: `alreadyBootstrapped` | قبلاً اجرا شده | طبیعی — ادامه دهید |
| ورود نمی‌شود | رمز تغییر کرده / دیتابیس خالی | اگر دیتابیس خالی: گام ۴؛ اگر رمز: از مدیر ادمین بخواهید ریست کند |
| cron-tick: `403` | CRON_SECRET نادرست/حذف | مقدار را در Environment Variables چک کنید → **Redeploy** |
| پاسخ‌ها کند (۱-۲ ثانیه) | خواب Neon | طبیعی پلن رایگان |
| یادآورها نمی‌آیند | جاب cron متوقف/حذف | تاریخچه اجرای cron-job.org + پنل سلامت سامانه |
| تغییر env اثر نکرد | envها فقط با redeploy اعمال می‌شوند | Deployments → ⋯ → Redeploy |
